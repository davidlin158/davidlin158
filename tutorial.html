0.1先理解三个词

这三个词你现在只需要知道大概，一周后自然就懂了：

  • 解释器（Python 本体）：真正执行你代码的程序。电脑里可以同时装好几个版本。
  • 包（package）：别人写好的代码库，比如 pandas。用 import pandas 就能用。
  • 虚拟环境（venv）：一个文件夹，里面装着这个项目专用的一套包。不同项目互不干扰——这是它存在的全部理由。

一句话打个比方：解释器是厨师，包是食材，虚拟环境是这道菜专用的一间小厨房。你不想做甜品时打翻了做川菜的辣椒罐。

1.1变量不是盒子，是标签

很多教程说「变量是装东西的盒子」，这个比喻在 Python 里会害了你。正确的理解是：变量是贴在数据上的标签，多个标签可以贴在同一份数据上。

a = [1, 2, 3]     # 创建一个列表，贴上标签 a
b = a             # 把标签 b 也贴到同一个列表上，没有复制！
b.append(4)       # 通过 b 改动这个列表

print(a)          # a 也变了，因为 a 和 b 指着同一份数据
print(a is b)     # is 问的是「是不是同一份数据」
[1, 2, 3, 4] True

这就是初学者最常见的一类 bug 的源头：你以为复制了，其实只是多贴了一个标签。真要复制，得说清楚：

b = a.copy()      # 或者 b = a[:]  或者 b = list(a)
b.append(99)
print(a, b)
print(a is b)
[1, 2, 3, 4] [1, 2, 3, 4, 99] False

为什么数字和字符串没这个问题？因为它们是不可变的——你没法「改动」一个数字 3，只能让标签改指向 4。列表、字典、集合是可变的，才会出现上面的情况。这个「可变 vs 不可变」的区分明天还会再遇到。

1.3字符串：数据清洗的主战场

下面这七个方法，你八周里每周都会用到。现在把它们敲一遍。

raw = "  Shanghai, CHINA  "

print(repr(raw.strip()))            # 去掉两端空白（最常用的一个）
print(raw.strip().lower())          # 转小写，用来统一大小写
print(raw.strip().replace(",", ";"))
print(raw.strip().split(", "))      # 按分隔符切开，得到列表
print("shanghai" in raw.lower())    # 包含判断
print(raw.strip().startswith("Sh")) # 前缀判断
print("-".join(["a", "b", "c"]))    # 把列表拼成字符串
'Shanghai, CHINA' shanghai, china Shanghai; CHINA ['Shanghai', 'CHINA'] True True a-b-c

为什么用 repr() 而不是直接 print？因为 print(" a ") 和 print("a") 看起来几乎一样，你分辨不出空白有没有去掉。repr() 会把引号和转义字符都显示出来。调试字符串时永远用 repr。

f-string：格式化输出

字符串前面加个 f，就能在 {} 里直接写变量和表达式。这是现在唯一推荐的写法。

name, gmv, rate = "上海", 1234567.891, 0.0325

print(f"{name} 的成交额是 {gmv}")
print(f"{name} 的成交额是 {gmv:,.2f} 元")   # , 千分位   .2f 两位小数
print(f"转化率 {rate:.2%}")                 # .2% 百分比，自动乘 100
print(f"{name:<6}|{name:>6}|{name:^6}|")   # 左对齐 右对齐 居中，做表格用
print(f"{gmv = }")                          # 加个等号，调试时打印变量名+值
上海 的成交额是 1234567.891 上海 的成交额是 1,234,567.89 元 转化率 3.25% 上海 | 上海| 上海 | gmv = 1234567.891

1.4真假值：Python 里「空」就是假

这条规则在数据清洗里用得极多，值得单独讲。if x: 判断的不只是 True/False：

falsy = [False, None, 0, 0.0, "", [], {}, set()]   # 这八个都是「假」
for v in falsy:
    print(f"{repr(v):<8} → {bool(v)}")
False → False None → False 0 → False 0.0 → False '' → False [] → False {} → False set() → False

所以清洗代码可以写得很短：

def clean_city(raw):
    s = (raw or "").strip()      # raw 是 None 时用空字符串兜底
    return s.title() if s else "未知"

for x in ["  shanghai ", "", None, "BEIJING"]:
    print(repr(x), "→", clean_city(x))
' shanghai ' → Shanghai '' → 未知 None → 未知 'BEIJING' → Beijing

但要小心：如果 0 是一个有意义的值（比如销售额为 0），if amount: 就会把它当成缺失漏掉。这时必须写 if amount is not None:。这是真实项目里非常常见的一个 bug。

跟我敲 · 15 分钟，清洗一列真实的脏城市名

在 Jupyter 里新建一个 notebook，一格一格敲下面的内容。

  1. 准备数据（真实数据就长这样，什么脏的都有）

    rows = ["  上海市 ", "上海", "SHANGHAI", "北京", " 北京市", None, "", "深圳市", "shenzhen"]

  2. 先看看直接去重会得到什么——体会一下问题有多大

    print(len(set(rows)), set(rows))
    9 {None, '深圳市', '上海', ' 北京市', 'SHANGHAI', '', ' 上海市 ', 'shenzhen', '北京'} 明明只有 3 个城市，却被当成了 9 个

  3. 一步步加清洗规则，每加一条就打印一次看效果

    ALIAS = {"shanghai": "上海", "shenzhen": "深圳", "beijing": "北京"}

def normalize(raw):
    s = (raw or "").strip()              # 1 兜底 + 去空白
    if not s:
        return "未知"                     # 2 空的统一成「未知」
    s = ALIAS.get(s.lower(), s)          # 3 英文名映射回中文
    if s.endswith("市"):
        s = s[:-1]                       # 4 去掉「市」字后缀
    return s

for r in rows:
    print(f"{repr(r):<14} → {normalize(r)}")
    ' 上海市 ' → 上海 '上海' → 上海 'SHANGHAI' → 上海 '北京' → 北京 ' 北京市' → 北京 None → 未知 '' → 未知 '深圳市' → 深圳 'shenzhen' → 深圳

  4. 验证效果

    cleaned = [normalize(r) for r in rows]     # 这个写法明天讲，先照抄
print(len(set(cleaned)), set(cleaned))
    4 {'上海', '北京', '深圳', '未知'} 9 个变 4 个，这就是数据清洗

name  = NAME.get(parts[0].lower(), parts[0])

    参考答案
    def to_amount(raw):
    s = (raw or "").strip().replace(",", "")   # 去千分位逗号
    if not s:
        return None
    try:
        return float(s)
    except ValueError:                          # "abc" 转不了会走到这里
        return None

for a in ["1,234.5", "", "998", None, "0", "abc"]:
    print(f"{repr(a):<10} → {to_amount(a)}")

WEEK 1 · DAY 2

四种容器：list、dict、set、tuple

用时约 3 小时
前置D1
学完你能不用任何库，手写出一份数据的分组统计
为什么先学这个

pandas 的 DataFrame 本质上就是「一堆列，每列是一个数组」。你今天手写的分组统计，第四周会变成一行 groupby。先用笨办法做一遍，以后才知道那一行到底替你做了什么。

2.1一张表决定用哪个

四个容器，选择标准其实只有两个问题：要不要保持顺序？要不要按名字取值？

容器写法什么时候用取一个元素多快
list[1, 2, 3]有顺序、会增删的一串东西（最常用）按位置：快
dict{"a": 1}按名字查值：ID → 记录、城市 → 销售额按键：极快
set{1, 2, 3}去重、判断「在不在里面」、求交集差集判断存在：极快
tuple(1, 2)不该被改的一组值，比如坐标、函数的多个返回值按位置：快

一条实用规则：如果你在写 if x in my_list: 而这个 list 有几千上万个元素，把它换成 set，会快几百倍。原因是 list 要一个个比对，set 直接算哈希定位。

2.2list：最常用的那个

nums = [3, 1, 4, 1, 5, 9, 2, 6]

# 取值：从 0 开始数，负数从末尾数
print(nums[0], nums[-1], nums[-2])

# 切片 [起点:终点]，终点不包含 —— 记住「左闭右开」
print(nums[1:4])      # 第 1、2、3 个
print(nums[:3])       # 前三个
print(nums[-3:])      # 后三个
print(nums[::2])      # 每隔一个取
print(nums[::-1])     # 反转
3 6 2 [1, 4, 1] [3, 1, 4] [9, 2, 6] [3, 4, 5, 2] [6, 2, 9, 5, 1, 4, 1, 3]
items = ["a", "b"]
items.append("c")          # 末尾加一个
items.extend(["d", "e"])   # 末尾加一串（注意和 append 的区别）
items.insert(0, "z")       # 插到指定位置

3.1if / elif / else：注意缩进就行

def grade(amount):
    if amount is None:          # 先处理特殊情况，这叫「早返回」
        return "缺失"
    if amount >= 500:
        return "高"
    elif amount >= 100:         # elif 只在上面都不成立时才判断
        return "中"
    else:
        return "低"

for a in [620, 199, 45, None]:
    print(a, "→", grade(a))
620 → 高 199 → 中 45 → 低 None → 缺失

写判断的两条实用习惯：①把特殊情况放最前面提前 return，能让主逻辑不用层层嵌套；②区间判断从大到小或从小到大排，中间不留缝——上面 >= 500 和 >= 100 就是这样，写反了会全落进第一个分支。

3.2for 循环的三个搭档

for 本身很简单，真正天天用的是这三个内置函数：

cities = ["上海", "北京", "深圳"]
amounts = [1200, 980, 1500]

for i in range(3):                       # range(n)：0 到 n-1
    print(i, end=" ")
print()

for i, c in enumerate(cities, start=1):  # 同时要下标和值
    print(f"{i}. {c}")

for c, a in zip(cities, amounts):        # 两个等长列表配对遍历
    print(f"{c} {a}")

看到 for i in range(len(x)) 就该警觉。需要值就直接 for item in x，需要下标和值就 enumerate，两个列表配对就 zip。用下标去索引是 C 语言的思维，在 Python 里几乎总有更清楚的写法。

3.3推导式：本节的重点

推导式就是把「造一个新列表」的循环压缩成一行。先看它和循环的一一对应关系：

# 循环写法
result = []
for x in nums:
    if x > 0:
        result.append(x * 2)

# 推导式写法 —— 顺序：先写要什么，再写从哪来，最后写筛选条件
result = [x * 2 for x in nums if x > 0]
#          ↑要什么   ↑从哪来      ↑筛什么
nums = [3, -1, 4, -1, 5, 9]

print([x * 2 for x in nums])                    # 变形
print([x for x in nums if x > 0])               # 筛选
print([x * 2 for x in nums if x > 0])           # 又筛又变
print([x if x > 0 else 0 for x in nums])        # 三元表达式：不筛掉，而是替换
[6, -2, 8, -2, 10, 18] [3, 4, 5, 9] [6, 8, 10, 18] [3, 0, 4, 0, 5, 9]

注意最后两行的区别，初学者最容易混：if 写在后面是筛选（元素会消失，长度变短）；if...else 写在前面是替换（长度不变）。清洗数据时你几乎总是想要后者——因为长度不变才能和其他列对齐。

字典推导式和集合推导式

sales = {"上海": 1200, "北京": 980, "深圳": 1500}

print({k: v / 10000 for k, v in sales.items()})           # 单位换成万
print({k: v for k, v in sales.items() if v > 1000})        # 筛选
print({v: k for k, v in sales.items()})                    # 键值对调
print({c[0] for c in sales})                               # 集合推导式：首字去重
{'上海': 0.12, '北京': 0.098, '深圳': 0.15} {'上海': 1200, '深圳': 1500} {1200: '上海', 980: '北京', 1500: '深圳'} {'上', '北', '深'}

什么时候不该用推导式

推导式不是越长越好。这三种情况请老老实实写循环：

  • 嵌套超过两层——没人读得懂 [y for x in a for y in x if ...] 再套一层
  • 循环体里有多个步骤或需要中间变量
  • 你需要在里面 print 调试

判断标准很朴素：一行写不下、或者读一遍要停顿两次，就拆回循环。

4.1一个函数的完整长相

def summarize(amounts, ndigits=1):
    """算一组金额的基本统计量。

    参数
        amounts:  数字列表，可以含 None
        ndigits:  结果保留几位小数，默认 1
    返回
        一个 dict：n / total / mean / max
    """
    valid = [a for a in amounts if a is not None]
    if not valid:                                  # 边界情况先处理掉
        return {"n": 0, "total": 0.0, "mean": None, "max": None}
    return {
        "n": len(valid),
        "total": round(sum(valid), ndigits),
        "mean": round(sum(valid) / len(valid), ndigits),
        "max": max(valid),
    }

print(summarize([199.0, 89.5, None, 320.0]))
print(summarize([], ndigits=2))
print(summarize([1.234, 5.678], ndigits=2))

这个函数里藏着五个好习惯，逐个说：

  1. 名字是动词：summarize、clean_city、load_orders。函数在「做事」，名字就该说清做什么事。
  2. docstring 写在第一行，用三引号。在 Jupyter 里按 Shift+Tab 就能弹出来看。

4.3那个著名的可变默认参数坑

def bad_append(item, bucket=[]):     # ✗ 千万别这么写
    bucket.append(item)
    return bucket

print(bad_append("a"))
print(bad_append("b"))               # 期待 ['b']，实际呢？
print(bad_append("c"))
['a'] ['a', 'b'] ['a', 'b', 'c']

原因：默认值只在函数定义那一刻创建一次，之后所有调用共用同一个列表。正确写法：

def good_append(item, bucket=None):
    if bucket is None:
        bucket = []                  # 每次调用都新建一个
    bucket.append(item)
    return bucket

print(good_append("a"))
print(good_append("b"))
['a'] ['b']

记忆口诀：默认值只能用不可变的东西——数字、字符串、True/False、None。想用 list 或 dict 当默认值，一律先写 None 再在函数体里建。

    """对任意一列数据做统计画像。"""
from collections import Counter
from datetime import datetime

DATE_FORMATS = ("%Y-%m-%d", "%Y/%m/%d", "%Y-%m-%d %H:%M:%S", "%Y%m%d")
BOOL_WORDS = {"true", "false", "yes", "no", "是", "否", "0", "1"}


def as_number(s):
    """能转成数字就返回数字，否则 None。"""
    try:
        return float(str(s).strip().replace(",", ""))
    except (TypeError, ValueError):
        return None


def as_date(s):
    for fmt in DATE_FORMATS:
        try:
            return datetime.strptime(str(s).strip(), fmt)
        except (TypeError, ValueError):
            continue
    return None


def guess_type(values, threshold=0.8):
    """看这一列里有多少比例能转成某种类型，超过阈值就认定为该类型。"""
    vals = [v for v in values if v]           # 只看非空的
    if not vals:
        return "空列"
    n = len(vals)
    if sum(as_number(v) is not None for v in vals) / n >= threshold:
        return "数字"
    if sum(as_date(v) is not None for v in vals) / n >= threshold:
        return "日期"
    if len(set(v.lower() for v in vals)) <= 2 and \
       all(v.lower() in BOOL_WORDS for v in vals):
        return "布尔"
    return "文本"

    为什么用 80% 阈值而不是 100%？真实数据里一列数字混进两三个「面议」「N/A」很常见。要求 100% 会把这列判成文本，反而丢掉了它本该有的统计量。代价是含 20% 以内脏值的文本列可能被误判——所以报告里必须同时列出「无法解析的值」，让人能复核。这个阈值本身就是一个可以在 README 里讨论的设计选择，写出来是加分项。

    def profile_column(name, values, top=3):
    """返回一列的画像 dict。"""
    n = len(values)
    clean = [(v or "").strip() for v in values]
    nonempty = [v for v in clean if v]
    kind = guess_type(nonempty)

    out = {
        "column": name,
        "type": kind,
        "n": n,
        "non_null_rate": round(len(nonempty) / n, 4) if n else 0.0,
        "n_unique": len(set(nonempty)),
        "top": Counter(nonempty).most_common(top),
        "bad_values": [],
    }

    if kind == "数字":
        nums = [as_number(v) for v in nonempty]
        out["bad_values"] = sorted({v for v, x in zip(nonempty, nums) if x is None})[:5]
        nums = sorted(x for x in nums if x is not None)
        if nums:
            mid = len(nums) // 2
            out.update({
                "min": nums[0],
                "median": nums[mid] if len(nums) % 2 else (nums[mid - 1] + nums[mid]) / 2,
                "max": nums[-1],
                "mean": round(sum(nums) / len(nums), 4),
            })
    return out

    中位数为什么自己算？因为这周不许用第三方库。注意偶数个元素要取中间两个的平均——这个细节很多人第一次会写错。第五周用 numpy.median 时，你会知道它内部就是这么干的。

    def profile_table(rows, id_column=None, top=3):
    """rows 是 list[dict]。返回 (每列画像, 行级问题)。"""
    if not rows:
        return [], [{"line": 0, "type": "空文件", "detail": ""}]

    columns = list(rows[0].keys())
    profiles = [profile_column(c, [r.get(c) for r in rows], top=top) for c in columns]

    issues = []
    for i, r in enumerate(rows, start=2):
        if any(v is None for v in r.values()):
            issues.append({"line": i, "type": "列数不足", "detail": str(r)[:60]})

    if id_column and id_column in columns:
        seen, dup = set(), []
        for i, r in enumerate(rows, start=2):
            key = (r.get(id_column) or "").strip().lower()
            if key and key in seen:
                dup.append({"line": i, "type": "id 重复", "detail": key})
            seen.add(key)
        issues += dup
    return profiles, sorted(issues, key=lambda d: d["line"])

    # profiler · CSV 数据体检工具

拿到一份没见过的 CSV，30 秒内知道它能不能用。只依赖 Python 标准库。

## 用法

```bash
python -m profiler data/orders.csv --id-column id --out report.csv
```

| 参数 | 说明 |
|---|---|
| `path` | CSV 路径（必填） |
| `--encoding` | 强制指定编码，默认按 utf-8 → utf-8-sig → gbk 顺序尝试 |
| `--id-column` | 主键列名，用于检查重复 |
| `--top` | 每列展示几个高频值，默认 3 |
| `--out` | 把列画像导出为 CSV |

## 它检查什么

- 每列的类型（数字/日期/布尔/文本）、非空率、唯一值个数、高频值
- 数字列的 min / 中位数 / 均值 / max，以及无法解析的脏值
- 行级问题：列数不足、主键重复

## 设计取舍

- **类型判断用 80% 阈值而非 100%**：真实数据里一列数字混几个「面议」很常见，
  要求全部可解析会让这一列被误判成文本，反而丢掉统计量。代价是含 20% 以内
  脏值的文本列可能被误判成数字——报告里会列出无法解析的值，便于人工复核。
- **坏行只记录不中断**：数据质量工具的价值在于一次跑完给出全部问题清单。
- **不修改原始数据**：所有清洗都产出新对象。

## 已知局限

- 日期格式只支持四种常见写法，不识别时区
- 大文件会全部读进内存，超过约 100 万行需要改成流式处理
- 中位数在含 NaN 的列上按剔除后计算，与 pandas 默认行为一致
